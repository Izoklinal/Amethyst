# Концепция главного интерфейса Amethyst

Этот документ описывает компоновку главного окна и границу между первым каркасом Workspace и более поздними фазами. Он не меняет `PRODUCT.md`, `ARCHITECTURE.md`, `DECISIONS.md` и `ROADMAP.md`.

Источники компоновки — текущая документация Visual Studio Code (Activity Bar, Primary Side Bar, Secondary Side Bar, Editor Groups, Panel, Status Bar, Command Palette) и справка Obsidian (Ribbon, левая и правая боковые панели, группы вкладок, Properties у заметки, Status Bar). Интерфейсы не копируются. Amethyst соединяет гибкость Workspace с интерфейсом для работы с заметками и сохраняет собственный визуальный характер.

Текущий фронтенд в `src/components/workspace/AppShell/AppShell.tsx` переключает Status, Explorer и Search в одной колонке и тем самым подменяет центральную область. Концепция заменяет этот паттерн: инструмент остаётся в боковой панели, центр остаётся редактором. Темы и токены в `src/styles/global.css` сохраняются.

## Визуальный характер

Хром тихий. Заметка — самая спокойная и просторная поверхность. Акцент один: уже заданные `--color-accent` (`#6750a4` в светлой теме и `#d0bcff` в тёмной). Области хрома отличаются соседними поверхностями и тонкой границей. Второй палитры и теней карточек нет.

Шрифт хрома — системный. Отдельный шрифт для чтения заметок этой концепцией не выбирается. Хром компактный, поля заметки больше полей панелей. Скругление общее, `--radius-medium`. Иконки позже приходят одним компонентом с небольшим набором SVG, без библиотеки иконок.

Светлая и тёмная темы продолжают атрибут `[data-theme]`. Компоненты берут только семантические токены. Новые повторяющиеся цвета, отступы и размеры областей добавляются в `src/styles/global.css`, а не в CSS Modules.

## Компоновка окна

Сверху вниз и слева направо:

```text
[ Activity bar | Primary sidebar | Editor groups        | Context sidebar ]
[              |                  | Bottom panel, hidden                   ]
[ Status bar                                                                ]
```

Command Palette — слой поверх окна, а не область раскладки.

### Activity bar

Узкая внешняя полоса слева. Она переключает инструмент Primary sidebar и не показывает содержимое инструмента. Снизу находится вход в настройки и тему. Полосу можно скрыть. Перенос наверх или вправо откладывается.

### Primary sidebar

Содержимое выбранного инструмента: файлы и поиск. Панель сворачивается целиком и не заменяет редактор. Ширина меняется разделителем и запоминается вместе с раскладкой.

### Editor

Центр окна. Здесь одна или несколько групп вкладок. Пустая группа остаётся на месте и показывает спокойное пустое состояние, а не закрывается.

### Context sidebar

Правая панель контекста открытой заметки: Outline и Backlinks. Пока заметки нет, панель скрыта. Проводник она не дублирует.

### Bottom panel

Область над строкой состояния. По умолчанию скрыта. Позже здесь появляются конфликты синхронизации и сообщения операций. Это не терминал и не вторая лента инструментов.

### Status bar

Тонкая полоса на всю ширину окна: имя хранилища, состояние сохранения и состояние синхронизации. Пока хранилища нет, полоса показывает готовность Core.

### Properties

Свойства живут в самой заметке, над текстом, как визуальный блок фронтматтера. Отдельная правая панель свойств не нужна: редактор свойств один, текст заметки остаётся главным.

## Поведение

### Вкладки

Открытие заметки создаёт вкладку в активной группе. Щелчок активирует вкладку, закрытие убирает её. Признак несохранённых изменений появится вместе с редактором. Клавиатура переключает следующую и предыдущую вкладку и закрывает текущую. Сочетания регистрируются в одном списке команд.

### Editor groups

Модель с самого начала — дерево групп, даже когда на экране одна группа. Вертикальное и горизонтальное разделение, перенос вкладки между группами и несколько сохранённых раскладок — целевое поведение. В первый каркас они не входят: это фаза 2 `ROADMAP.md`. Закрытие последней вкладки оставляет пустую группу.

### Панели

Primary sidebar, Context sidebar и Bottom panel показываются и скрываются независимо. В первом каркасе меняется ширина только Primary sidebar. Свободный перенос панелей между краями окна — фаза 2. Сброс раскладки возвращает порядок, описанный выше.

### Command Palette

Палитра открывается поверх окна, поле сразу получает фокус, Escape закрывает её. Список фильтруется по названию команды. Быстрое открытие заметки использует ту же оболочку, но появляется вместе с хранилищем. Первые команды каркаса: показать или скрыть три области, сменить тему, вернуть фокус в редактор.

### Состояние раскладки

Раскладка — состояние интерфейса. Она не пишется в хранилище и не становится копией заметок. Пока нет инфраструктуры настроек, допустимо локальное хранение в приложении, тем же способом, что и тема. Позже оно переезжает в настройки Amethyst, отдельно от файлов Obsidian.

## Компоненты

Новый общий компонент появляется только при втором использовании. Для каркаса это `IconButton` и `Resizer`. Обычные кнопки боковой панели заранее в библиотеку не выносятся.

```text
src/components/workspace/
  Workbench/
  ActivityBar/
  PrimarySidebar/
  EditorArea/
  EditorGroup/
  EditorTab/
  ContextSidebar/
  BottomPanel/
  StatusBar/
  CommandPalette/
src/workspace/
  layoutState.ts
  commands.ts
```

`Workbench` собирает области. `EditorArea` рисует группы. Инструменты регистрируются во внутреннем списке представлений, без API плагинов. Доменные операции по-прежнему идут через `src/api/` в Rust Core. React не читает файлы хранилища сам.

При реализации каркаса текущие `Sidebar`, `StatusView` и `PlaceholderView` уступают место этим областям. Status как отдельный экран исчезает: строка Core переходит в Status bar.

Стили компонентов — CSS Modules. Повторяющиеся визуальные значения — семантические токены. Инлайн-стили допустимы только для вычисленной ширины разделителя.

## Первый каркас

Первый каркас строится ещё без заметок и хранилища:

- Пять областей и строка состояния на токенах и CSS Modules.
- Activity bar с пунктами Explorer, Search и темы. Содержимое боковых панелей — короткие пустые состояния.
- Одна группа с одной пустой вкладкой.
- Скрытие боковых панелей и нижней панели.
- Разделитель ширины Primary sidebar.
- Command Palette с командами раскладки и темы.
- Светлая и тёмная темы без новой визуальной системы.

## Вместе с функциями MVP

Эти элементы появляются вместе с соответствующими возможностями, а не в пустом каркасе:

- Дерево файлов, поиск, вкладки заметок, Live Preview, Reading Mode и блок Properties.
- Outline и Backlinks в правой панели.
- Восстановление открытых вкладок и ширин.
- Быстрое открытие заметки через ту же палитру.
- Сообщения синхронизации в нижней панели.

## Фаза 2 и дальше

Эти возможности заложены в модель, но не строятся заранее:

- Несколько групп, Split View и перетаскивание вкладок.
- Перенос панелей между краями и несколько именованных раскладок.
- Graph, Canvas, Calendar, Bases и плагины.
- Настройка сочетаний клавиш и полный экран настроек.

## Соответствие документам

- `PRODUCT.md`: клавиатура, палитра команд, настраиваемое рабочее место, внимание к заметкам и темы. Совместимость с Obsidian относится к файлам, а не к копированию его интерфейса.
- `ARCHITECTURE.md`: независимые компоненты Workspace, сохранение раскладки отдельно от хранилища. Плагины для первого каркаса не требуются.
- `DECISIONS.md`: ADR-009, React как интерфейс, десктоп первичен.
- `ROADMAP.md`: вкладки, скрытие панелей и изменение ширины совпадают с фазой 1. Несколько групп и произвольные раскладки остаются фазой 2.
- Правила стилей: токены, CSS Modules, общие компоненты только при повторном использовании, без нового фреймворка стилей.
- Целостность данных: концепция не описывает запись заметок и не хранит их содержимое в состоянии интерфейса.
